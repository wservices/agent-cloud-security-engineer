# 0.2.0 — tested offline analysis scripts

Deepened the `cloud-security-engineer` role from scaffold to a tested script
layer. All scripts are offline, read-only, side-effect-free, and stdlib-first
(PyYAML only for YAML catalogs); they consume EXPORTED cloud config/state/findings
JSON and never call a cloud API.

Added `scripts/`:
- `iam_policy_audit.py` — flag wildcards, `NotAction`, condition-less Allow, and
  privilege-escalation-prone actions in an AWS IAM policy document.
- `sg_exposure.py` — flag `0.0.0.0/0`/`::/0` security-group ingress, weighting
  sensitive ports (22/3389/3306/5432/6379/27017/9200) and over-broad ranges.
- `cspm_findings_parse.py` — normalize a Prowler/ScoutSuite-style findings export
  (native JSON, OCSF, or NDJSON) and summarize by service/severity/status.
- `benchmark_map.py` — map normalized findings onto a CIS control catalog
  (YAML/JSON) for per-control pass/fail and overall coverage/compliance %.
- `key_rotation_audit.py` — from a KMS key inventory, flag rotation disabled,
  stale/never-rotated keys, and wildcard key policies (rotation METADATA only).
- `cloud_report_build.py` — assemble a severity-ranked, service-grouped Markdown
  posture report from normalized findings.

Skills now script-backed (each `## How to Run` + `## Verification` invokes its
script with a real example): `iam-least-privilege-review`,
`cloud-network-and-exposure-review`, `cloud-posture-review-cspm`,
`cloud-benchmark-compliance`, `secrets-and-key-management-review`,
`cloud-security-reporting` — all bumped to 0.2.0, with `python3` added to their
prerequisites.

Tests: added one behavior-contract test file per script under `tests/` (flagged
and clean cases, severities, compliance %, rendered report); kept
`tests/test_scaffold.py`. `python3 -m pytest tests -q` passes.
